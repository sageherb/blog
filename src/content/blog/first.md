## 왜 아스트로?

예전부터 블로그를 직접 만들고 싶었는데, 이번에 Astro로 블로그를 완성했다.

처음 블로그를 만들기 위해 이것저것 찾아보면서`Jekyll`, `Gatsby`도 고려했지만, Astro를 알게 된 뒤 이걸로 결정했다. 일단 공식 문서가 한글도 지원하고 굉장히 잘 되어 있어서 블로그 만들기 튜토리얼만 따라해도 금방 적응할 수 있었고, 아일랜드 아키텍처 같은 철학도 마음에 들었다.

Velog나 Medium도 생각 안 한 건 아니지만, 직접 커스텀이 불가능한 영역이 있고 직접 만들고 싶어서 여기까지 왔다.

부트 캠프를 다니는 동안에도 블로그 만들기는 몇 번 시도했지만, 강의와 프로젝트, 블로그까지 병행하기에는 좀 버거웠다. 그래서 부트 캠프를 끝내고 취업 준비를 하면서 본격적으로 만들게 됐다.

처음엔 아스트로에서 제공하는 테마를 이용해서 빠르게 만들 생각이었다. 그런데 내가 원하는 가볍고 깔끔한 느낌의 테마가 없었고, 마음에 드는 테마는 빌드 에러가 터져서 결국 처음부터 만들게 됐다.

배포는 아스트로 튜토리얼에서 나온 Netlify를 이용했는데, 리전이 미국이라 네트워크 속도가 조금 느렸다. 리전을 바꾸는 기능은 유료라서 Vercel로 옮겼고, 도메인도 사버림. 내 도메인 2만 원도 안 한다! (ㅋㅋ)

블로그를 직접 만들면서 트러블 슈팅이 몇 가지 있었다.

### 1. 디자인 시스템

디자인 시스템은 항상 어렵다. 나는 디자인을 따로 배워본 적도 없고, 프로젝트를 하면서 여러 불편함을 겪고 해결책을 찾다가 Radix를 알게 되면서 디자인 시스템에 대해 이것저것 깨달은 점은 있었지만, 색상을 정하고 모든 페이지에 일관성을 주는 과정은 언제나 고민이 많이 필요하다.

내가 개발자 닉네임으로 Sage를 쓰는 건 실명과 비슷한 영어 이름이기 때문인데, 현자라는 뜻은 너무 거창해서 허브 향신료인 세이지 쪽으로 정하게 됐고, 그래서 SageHerb를 쓰게 됐다.

그래서 색상도 그린 계열로 잡았다. 나는 좀 쿨한 계열의 색상을 좋아해서, 쿨 그린 계열과 그레이 스케일은 zinc로 정했다.

처음에는 여기저기 그린 컬러를 많이 썼더니 블로그가 너무 난잡해져서, 전체적으로는 그레이 스케일을 쓰고 강조할 부분에만 악센트를 주는 방식으로 정리했다. 의외로 컬러를 정하고 토큰을 세부적으로 나누는 과정이 꽤 오래 걸렸다. 진짜.

### 2. Claude Code + MCP

최근 개발 트렌드가 많이 바뀌고 있고, AI를 쓰지 않으면 도태될 것 같아 블로그는 Claude Code와 MCP를 적극적으로 이용해봤다.

여러 정보를 찾아보면서 일단 전역적인 `CLAUDE.md`를 작성했고, 프로젝트 안에도 따로 `CLAUDE.md`를 만들었다. Astro가 MCP 서버를 제공하고 있어서 Astro MCP를 연결해 기존 철학을 최대한 유지하도록 했다.

그런데도 스크립트를 바닐라 JS로 전부 작성해버려서, 나중에 `Preact`를 이용해 아일랜드 아키텍처 형태로 리팩토링하는 과정이 필요했다.

사실 블로그를 만들면서 직접 코드를 쓴 건 거의 없다. 리팩토링까지 Claude Code를 이용했음... 토큰 살살 녹아요.

중간중간 토큰 한계에 도달할 때마다 코덱스를 이용했는데, 코덱스용 `AGENT.md`까지 따로 작성해야 했다.

최근에 카카오톡에서 코덱스 프로 사용권을 저렴하게 판매하길래 고민했는데, 카카오 계정을 연결해야 한다는 점이 좀 찜찜해서 구매하지 않았다. 그런데 토큰이 살살 녹을 때마다 후회했음.

### Pagefind

블로그 검색 기능은 `Pagefind`라는 라이브러리를 사용했다. SSG 구조에 잘 맞고, 따로 서버를 두지 않으면서 콘텐츠를 관리하는 현재 프로젝트에도 가장 적합하다고 생각했기 때문이다.

근데 이 라이브러리는 빌드 시점에 인덱스를 생성하기 때문에 개발 서버에서는 검색 기능이 동작하지 않는다. (ㅋㅋ)

심지어 검색 input 스타일을 바꾸는 것도 매번 빌드를 하고 프리뷰를 돌려봐야 했고, 검색어를 지우는 `X` 아이콘 하나 넣는 것도 Pagefind에서 제공하는 UI 코드를 다 뜯어보고 수정한 뒤 다시 빌드해서 프리뷰로 확인해야 했다.

이것 때문에도 시간을 꽤 많이 잡아먹은 것 같다.

### Tailwind CSS Typography

이 블로그는 마크다운 콘텐츠를 정적으로 서빙하고 있고, 마크다운 스타일링을 적용하려고 찾아보다가 `Tailwind CSS`에서 제공하는 `prose` 기능이 있다는 걸 알게 됐다.

테일윈드는 MCP 서버를 따로 제공하지 않아서, AI한테 명령을 내리면 테일윈드 클래스가 아닌 CSS를 일일이 수정해서 공식 페이지에 있는 정보를 하나하나 떠먹여주면서 구체적으로 프롬프트를 주지 않으면, Claude가 우왕좌왕하는 느낌이었다.

전체적인 폰트 크기를 한 단계 줄이라고 했더니 모든 마크다운 클래스를 하나하나 잡아서 폰트 사이즈를 전부 줄여버리기도 했는데, 차라리 이건 직접 수정하는 게 더 빠르지 않을까 싶은 순간이 많았다.

## 결론

아무튼, 처음으로 Claude Code와 페어 프로그래밍을 하면서 블로그를 만드는 과정은 꽤 재밌었다.

직접 도메인을 사고 배포도 하고, 나만의 공간을 만드는 건 프로젝트와는 또 다른 재미가 있었다.

이제 이 공간을 하나하나 채워 넣어야지.
